# 작업 기록 — Obsidian (항상 적용)

작업 단위의 **커밋 → Codex 리뷰(지적 반영·재커밋 포함)가 모두 끝난 뒤**, 최종 상태를 옵시디언 MCP 로 여태호 저장소 `여태호-project/` 에 **1회** 기록한다. 사전 허락 없이 자동으로 기록하고, 기록 후 노트 경로를 보고한다. 양식은 `.claude/templates/obsidian-notes.md` 를 읽고 그대로 따른다.

## 어디에

- **서비스명은 `기술파악` 고정.** 모듈(`sources/`, `pipeline/`, `notify/`)은 서비스가 아니라 기능 노트 단위다.
- **프로젝트 노트** — `여태호-project/프로젝트/기술파악-Hub/기술파악.md`(허브) + `spoke/<기능명>.md`(기능) + `spoke/기술파악 - {폴더·파일 역할 지도|런타임 플로우|파일·함수 레퍼런스|결정 기록}.md`(상세 4종).
- **일일 노트** — `여태호-project/일일작업내역/YYYY-MM-DD(N일차)/기술파악 - <작업 제목>.md`. 항상 새 파일. 날짜 폴더가 없으면 기존 최대 일차 +1 로 만든다. `아사달/일일작업내역/` 일차와는 별개.
- 빈 폴더는 vault 목록에 보이지 않으므로 폴더를 탐색하지 말고 위 경로에 `vault_write` 로 직접 쓴다.

## 무엇을

- **허브** — 개요 + 기능 현황 표 + spoke 링크만. 항상 짧게.
- **기능 노트** — 독립된 과제·기능 단위일 때만 새로 만든다. 한두 커밋 잔수정은 기존 기능 노트와 허브 표만 갱신한다.
- **상세 4종** — 참조 정보. 관련 내용이 바뀐 작업일 때만 갱신한다. 결정 기록에는 **기각한 대안과 이유**를 반드시 남긴다.
- **기존 노트 갱신** — 의미 없어진 내용은 그 노트 안에서만 덮어쓰고 `updated` 를 고친다. 이력은 일일 노트가 맡는다.
- **일일 노트** — 기능 노트를 `[[<기능명>]]` 으로 링크해 양방향 연결. 기능 노트가 없는 잔수정은 `[[기술파악]]` 허브로.

## 스타일 — 학습노트 양식

- frontmatter `tags` `created` (프로젝트 노트는 `updated` 추가).
- 맨 위 `> [!summary]` 콜아웃 한두 문장.
- H2 로 나누고 항목당 2~4줄 문단. **불릿 하나에 긴 문장을 대시로 이어붙이지 않는다.**
- 열거 사실은 표, 흐름·구조는 코드블록, 핵심 수치·결론은 **굵게**.
- `[[링크]]` 를 적극 사용한다. 관련 학습노트도 연결한다.
